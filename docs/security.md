# Security model

`rivet session` is an outbound-only MCP tunnel client. It does not open an inbound listener.

## Capability boundaries

```text
Workspace
  authority: current directory at startup
  enforcement: capability-based file access + native OS sandbox

Top-level executable
  authority: --allow-command NAME=EXECUTABLE
  enforcement: MCP command-name lookup

argv
  authority: MCP request
  semantics: opaque argv passed directly to the registered executable
  Rivet does not interpret shell syntax

Environment
  runtime PATH: captured by Rivet at startup
  Rivet-owned sandbox variables: generated by Rivet
  user/application variables: only --pass-env NAME
  MCP requests cannot add or override environment values

Network
  default: denied to child commands
  authority: --network at startup

Process limits
  authority: fixed Rivet limits
```

The MCP caller cannot add executables, environment variables, filesystem roots, or network access after the session starts.

## Native sandbox

- The current directory is the only workspace root.
- Rivet filesystem tools use capability-based paths and cannot leave that workspace.
- Every child command is OS-sandboxed before execution. There is no unsandboxed command-execution mode.
- macOS uses `/usr/bin/sandbox-exec` (Seatbelt).
- Linux and WSL2 use `bubblewrap`. Ubuntu 24.04 requires the distro `bwrap-userns-restrict` AppArmor profile for unprivileged user namespaces.
- If the required sandbox backend is unavailable, session startup fails closed.
- Child processes may spawn descendants, but descendants inherit the same sandbox.
- Child network access is disabled by default. `--network` enables it without removing filesystem isolation.
- When the workspace is a linked Git worktree, commands launched as the registered `git` executable and their descendants receive the narrow Git metadata access required for that worktree.
- Sandbox `HOME`, `TMPDIR`, and `CARGO_HOME` are Rivet-owned. Required toolchain locations are exposed according to the platform sandbox rules.

Command registration and the OS sandbox solve different problems: registration controls which top-level executable MCP may request; the sandbox limits what that executable and its descendants can do.

## Environment

Child processes begin with an empty environment. Rivet then applies:

1. the startup `PATH` required for registered tools to locate their own executables;
2. Rivet-owned sandbox environment;
3. values explicitly captured with `--pass-env NAME`.

`--pass-env` values are captured once when the session is created. Missing variables, duplicate names, invalid names, and names reserved by Rivet fail startup. Values remain in process memory only and are not printed in the session summary or exposed through MCP metadata.

Tunnel credentials are never included in child environment unless a credential name were separately exposed through an allowed mechanism; Rivet's own control-plane credentials are not automatically passed to children.

## Credentials

When credentials are entered interactively, Rivet disables terminal echo for both the tunnel ID and runtime API key. Rivet keeps both values in process memory and does not persist them. The runtime API key is sent only in the Bearer authorization header. HTTP redirects are disabled. Production uses `https://api.openai.com`; overriding the control-plane URL requires the explicit unsafe test opt-in.
